# KEYS — everything this repo binds, in one place

Generated by `bin/dot-keys`. Do not edit by hand: the descriptions are
pulled from the comments and `desc` fields in the configs themselves, so
this file cannot drift from what the editors actually do.

Sources:

- Sublime: `~/repos/me/dotfiles/sublime/User/Default.sublime-keymap`
- Neovim: `~/.config/nvim/init.lua`
- Helix: `~/repos/me/dotfiles/helix/config.toml`
- GitSavvy: `~/Library/Application Support/Sublime Text/Installed Packages/GitSavvy.sublime-package`

How to search this:

- Sublime: `F1` opens it, or `Keys: search bindings` in the palette
- Neovim: `<leader>?` is a live fzf picker over the real keymaps
- Helix: `<space>i` (hx-keys, Helix bindings only)
- Terminal: `dot-keys | fzf` or just grep this file

## Helix

### quickfix / compile mode

- <space>m : build (auto-detected) into the quickfix buffer
- <space>M : same, but keep the cursor where it is
- <space>q : refresh / reopen the quickfix buffer
- A-ret    : jump to what the line points at — path:row:col, or a spot in a diff

### git changes as a jumpable buffer

- <space>vs : which FILES changed        ("what am I working on")
- <space>vc : which LINES changed vs HEAD, staged and unstaged both
- <space>vb : which LINES changed vs the merge-base with main/master
- <space>vd : the DIFF vs HEAD, syntax highlighted
- <space>vr : the DIFF vs merge-base — the PR review one
- <space>vp : the review diff in a tmux popup through delta (reading only)

### harpoon: per-project pinned files

- <space>za : pin the current file+line
- <space>ze : edit the pin list as a buffer
- <space>zl : list the pins in the statusline
- <space>zc : clear all pins
- A-1 to A-9 : jump to pin N

### help

- <space>i  : this cheatsheet, since Helix cannot label custom bindings
